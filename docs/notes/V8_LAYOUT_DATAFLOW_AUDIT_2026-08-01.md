# v8 Layout and Dataflow Audit, 2026-08-01

## Question

CKE generated runtimes contain standalone token-major/head-major conversions.
This audit separates their logical tensor traffic from cache traffic and
external DRAM traffic, then checks whether they explain the measured prefill
gap.

## Measured workload

- Model: Qwen3-VL 8B Q4_K_M decoder with Q8_0 vision projection
- Shape: 1,008 visual prefix tokens plus 27 text/template tokens
- Runtime: native `ck-cli-v8`
- Threads: 20 CK workers, OpenMP disabled
- CPU: Intel Core i7-14700T, AVX2/FMA
- Prefill wall time: 24.76-25.80 seconds in uninstrumented/perf/VTune runs

## Three different byte counts

1. Logical layout traffic is calculated from tensor dimensions and generated
   copy passes. It describes what CKE requested.
2. Cache traffic is generated by all loads and stores, including repeated
   projection-kernel accesses. It can be much larger than logical tensor size.
3. External DRAM traffic counts bytes crossing the integrated memory
   controller. Temporary layout buffers can remain in cache and therefore do
   not necessarily reach DRAM.

These quantities must not be treated as interchangeable.

## Static generated-IR result

| Runtime section | Conversions | Payload | Bytes copied | Logical read/write |
|---|---:|---:|---:|---:|
| Vision encoder | 27 | 119.60 MiB | 239.20 MiB | 478.41 MiB |
| Decoder mixed prefill | 144 | 1.42 GiB | 2.84 GiB | 5.69 GiB |
| Combined | 171 | about 1.54 GiB | about 3.08 GiB | about 6.16 GiB |

All 171 operations are standalone, avoidable, unresolved by kernel maps, and
serial. They therefore have no current cross-thread false-sharing risk. They do
cause extra cache traffic and serial work.

## Memory-controller measurement

Linux `perf` integrated-memory-controller counters measured the production
mixed-prefill run:

- DRAM reads: 105,765.98 MiB
- DRAM writes: 42,932.44 MiB
- DRAM total: 149,090.56 MiB
- Average external bandwidth: approximately 6.02 GiB/s

VTune independently measured:

- Average DRAM bandwidth: 6.096 GB/s
- Observed maximum: 34.4 GB/s
- Measured platform maximum: 39.0 GB/s
- Time at high bandwidth utilization: 0.3%
- DRAM bandwidth bound: 0.3% of elapsed time

A 20-thread LIKWID AVX copy benchmark measured 32.8 GB/s of logical copied
bytes and approximately 38.6 GiB/s at the memory controller. The CKE workload
therefore used only about one sixth of available sustained DRAM bandwidth.

## VTune attribution

Top CPU-time functions were:

| Function | CPU time |
|---|---:|
| `gemm_q4_packed_vnni_x8_q8k_4m_thread_fn.part.0` | 29.83 s |
| `dot_q6_k_q8_k_avx2` | 12.48 s |
| Q4 packed superblock provider | 3.29 s |
| `memset` | 2.59 s |
| FP16 attention providers combined | about 1.7 s |
| `memmove` | 0.228 s |

The dominant Q4 provider was primarily L1-bound and only weakly DRAM-bound.
The standalone layout copies account for roughly 0.9% of serial wall time,
consistent with their `memmove` attribution. Removing them is correct, but it
cannot close the multi-second projection gap by itself.

## Advisor result

Advisor reported 26 vectorized loops, 47.44 GFLOP/s, and 216.23 GINTOP/s. Its
largest loop groups were the same Q4 and Q6 projection providers identified by
VTune. Advisor's arithmetic-intensity model is less descriptive for quantized
integer unpack/dot-product kernels than for FP32 GEMM, so provider-level timing,
dynamic instruction counts, and independent byte accounting remain necessary.

## Policy

Standalone runtime layout conversion should not be invisible. Lowering should
prefer a producer that writes a consumer-compatible layout, then a strided
consumer, and insert a first-class mapped `layout_convert` provider only as a
fallback. Internal packing remains valid when a stitched benchmark proves its
reuse pays for the conversion.

Any parallel layout provider must declare destination-range ownership. Tests
must reject overlapping cache-line writers and unresolved ownership before the
provider is promoted.

## Reproduction

Static accounting:

```bash
python3 version/v8/scripts/audit_layout_dataflow_v8.py \
  --ir /path/to/lowered_prefill.json \
  --tokens 1035 \
  --json-out build/layout_dataflow_audit.json
```

Strict promotion gate:

```bash
python3 version/v8/scripts/audit_layout_dataflow_v8.py \
  --ir /path/to/lowered_prefill.json \
  --tokens 1035 \
  --fail-on-avoidable
```

Actual external DRAM traffic requires hardware counters, for example:

```bash
perf stat -a -e \
uncore_imc_free_running/data_read/,\
uncore_imc_free_running/data_write/,\
uncore_imc_free_running/data_total/ \
-- ./build/ck-cli-v8 ...
```

VTune Memory Access supplies bandwidth-over-time, cache-level bounds, and
function attribution. `perf c2c` is appropriate for validating suspected
cross-thread false sharing after a parallel provider exists; it is not useful
for the current serial transpose loops.
